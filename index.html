Month-end reporting for a major retail client

Five month-end files for a major retail client, including a 270K-row register, now built automatically and saving 1–2 hours every period.

Context
A large retail customer gets a set of reports from us at every month end. They were put together by hand, and the biggest one has around 270,000 rows, more than our reporting tool can hand over in one go.
Action
I built two automated flows so the reports build and deliver themselves each period.

  • Creates a new folder for the period on the customer's shared site
  • Builds five files (usage, category, inventory, price list and invoice register) from Excel templates
  • Pulls the 270,000-row invoice register in chunks of 7,000 rows and stitches them back together
  • Emails the team once everything is delivered
Result
In a full test, all ~270,000 rows came through and the totals matched the source. The reports now run on the customer's fiscal calendar and save 1 to 2 hours of manual work every period. I've since automated another customer's month-end report too, saving another 20 to 30 minutes.
Learning
My first two approaches didn't work because the data source had limits I hadn't checked. Rebuilding the data as one simple, numbered table made everything easier. Now I check what the source can do before designing around it.

Process improvement, AutologiQ, 2022–2024

Unbilled invoice recovery at AutologiQ

Caught $50,000+ in unbilled parts by comparing two systems, recovered all of it, and closed the gap for good.

Illustration

Tap the visual to view it larger

Read the case studyHide the case study
Context
At AutologiQ, we ordered parts for partner repair shops, paid the suppliers, then billed the shops through Square. Part of my job was reconciling supplier statements each month and recording every invoice in QuickBooks, both as our expense and against the shop that owed us for it.
Action
While reconciling, I spotted shop invoices in QuickBooks that had been open for months. I compared them against Square and found the gap: those invoices had never been issued.
  • Traced each outstanding invoice in QuickBooks back to Square to confirm it was never billed
  • Reviewed every open invoice with the manager who worked closest with the shops, so he could walk each shop through it and collect
  • Set up a new process with the team: sales reps send me the invoice as soon as they sell parts to a shop, I bill it in Square right away, then record it in QuickBooks on both our expense side and the shop's side
  • Followed up with any shop that hadn't paid within 1 to 2 weeks
Result
Caught over $50,000 in parts that hadn't been billed, and recovered all of it. With the new process, shops are invoiced right away and any late payment is followed up within a couple of weeks.
Learning
Neither system looked wrong on its own. The gap only showed up when I compared QuickBooks with Square. Since then I pay close attention to the points where information passes from one system or person to the next, because that's where things go missing.

SQL, DatabricksCombines open and closed receivables, converts the ERP's date format, finds each customer's group, and flags discounts taken after the discount window closed.

-- Open and closed receivables in one set
WITH all_payments AS (
    SELECT company_id, customer_id, invoice_id, txn_date_cymd, invoice_date_cymd,
           payment_amt, discount_taken_amt, valid_to, is_deleted
    FROM ar_payment_closed
    UNION ALL
    SELECT company_id, customer_id, invoice_id, txn_date_cymd, invoice_date_cymd,
           payment_amt, discount_taken_amt, valid_to, is_deleted
    FROM ar_payment_open
),
dated AS (
    SELECT *,
        -- ERP dates carry a century digit; the last six are yyMMdd
        to_date(right(invoice_date_cymd, 6), 'yyMMdd') AS invoice_date,
        to_date(right(txn_date_cymd, 6), 'yyMMdd')     AS payment_date
    FROM all_payments
    WHERE valid_to IS NULL AND is_deleted = FALSE   -- current records only
)
SELECT
    p.invoice_id,
    p.customer_id,
    p.invoice_date,
    p.payment_date,
    p.discount_taken_amt,
    t.terms_desc,
    t.discount_days,
    datediff(p.payment_date, p.invoice_date) AS days_to_pay,
    -- the check: discount taken, but paid after the discount window
    CASE WHEN p.discount_taken_amt > 0
          AND datediff(p.payment_date, p.invoice_date) > t.discount_days
         THEN 'Outside terms' END              AS discount_flag,
    -- group can be set on the customer, its price group or its rebate group
    coalesce(g1.group_id, g2.group_id, g3.group_id) AS cust_group
FROM dated p
LEFT JOIN customer_master c
  ON  p.company_id = c.company_id AND p.customer_id = c.customer_id
  AND c.valid_to IS NULL AND c.is_deleted = FALSE
LEFT JOIN payment_terms t
  ON  c.terms_code = t.terms_id AND t.valid_to IS NULL
LEFT JOIN customer_groups g1 ON c.company_id = g1.company_id AND c.customer_id   = g1.customer_id
LEFT JOIN customer_groups g2 ON c.company_id = g2.company_id AND c.price_group   = g2.customer_id
LEFT JOIN customer_groups g3 ON c.company_id = g3.company_id AND c.rebate_group  = g3.customer_id

SQL, DatabricksOne row per receipt layer of stock, with its cost and an age bucket for the provision report.

SELECT
    CONCAT(s.company_id, '-', s.location_id, '-', s.item_id) AS item_key,
    cl.receipt_date,
    cl.qty                                                   AS layer_qty,
    cl.unit_cost,
    cl.layer_cost,
    -- aged as of the day the snapshot is pulled
    CASE
        WHEN cl.receipt_date IS NULL                              THEN NULL
        WHEN MONTHS_BETWEEN(CURRENT_DATE(), cl.receipt_date) < 6  THEN '< 0.5 Year'
        WHEN MONTHS_BETWEEN(CURRENT_DATE(), cl.receipt_date) < 12 THEN '0.5-1 Year'
        WHEN MONTHS_BETWEEN(CURRENT_DATE(), cl.receipt_date) < 18 THEN '1-1.5 Years'
        WHEN MONTHS_BETWEEN(CURRENT_DATE(), cl.receipt_date) < 24 THEN '1.5-2 Years'
        ELSE '2+ Years'
    END                                                      AS age_bucket
FROM item_inventory_snapshot AS s
-- one row per cost layer (each receipt of stock)
LEFT JOIN inventory_cost_layers AS cl
    ON  cl.item_key = s.item_key
    AND cl.valid_to IS NULL

DAX queryBuilds a customer's sales file in the exact column layout their system expects, with fallbacks for missing names and text formatting so IDs keep their leading zeros.

DEFINE
VAR RAW =
    CALCULATETABLE (
        ADDCOLUMNS (
            SUMMARIZE ( Sales,
                'Timeline'[Date], Sales[Location Key], Sales[Ship To Key],
                'Ship To'[Ship To Name], 'Customer'[Customer Name],
                'Item'[Item #], 'Item'[Brand], 'Item'[Vendor], 'Item'[UPC] ),
            "Transaction Quantity", CALCULATE ( SUM ( Sales[Shipped Qty] ) ),
            "Transaction Volume",   CALCULATE ( SUM ( Sales[Net Sales] ) ),
            "Distributor ID", SWITCH ( Sales[Location Key],
                "10-101", "DIST01",
                "10-102", "DIST02",
                "OTHER" ),
            -- fall back when the ship-to name or brand is missing
            "Ship To Customer Name", COALESCE ( 'Ship To'[Ship To Name], Customer[Customer Name] ),
            "Brand Name",            COALESCE ( 'Item'[Brand], 'Item'[Vendor] )
        ),
        Customer[Customer Group] IN { "CUSTOMER A" },
        NOT ( LEFT ( Sales[Ship To Key], 2 ) = "W-" )   -- exclude internal transfers
    )
EVALUATE
SELECTCOLUMNS ( RAW,
    "Distributor ID Number",         [Distributor ID],
    "Date",                          FORMAT ( [Date], "YYYY-MM-DD" ),
    "Ship To Customer Name",         [Ship To Customer Name],
    "Distributor Item Number (DIN)", FORMAT ( [Item #], "0" ),
    "Brand",                         [Brand Name],
    "Transaction Quantity",          [Transaction Quantity],
    "Transaction/Extended Volume",   FORMAT ( [Transaction Volume], "0.00" ),
    "UPC",                           "'" & [UPC]   -- keeps leading zeros in Excel
)

DAX queryThe query the month-end flow runs: one fiscal period for one customer, shipped lines only, with net cost after the customer's fee and freight.

DEFINE
    MEASURE 'Measures'[Customer Net Cost] =
        -- strip the customer's fee and freight from net sell, line by line
        SUMX ( Sales, Sales[Net Sell] / ( 1 + Sales[Fee %] + Sales[Freight %] ) )

    VAR CustomerOnly = TREATAS ( { "CUSTOMER A" }, Customer[Customer Group] )
    VAR ShippedOnly =
        FILTER ( KEEPFILTERS ( VALUES ( Sales[Shipped Qty] ) ), Sales[Shipped Qty] <> 0 )
    -- period start and end are filled in by the flow from its fiscal period step
    VAR FiscalPeriod =
        FILTER ( KEEPFILTERS ( VALUES ( Timeline[Day] ) ),
            Timeline[Day] >= DATE ( 2026, 6, 28 )
                && Timeline[Day] < DATE ( 2026, 8, 1 ) )

EVALUATE
SUMMARIZECOLUMNS (
    Item[Location],
    Customer[Customer #],
    Sales[Ship To #],
    Sales[Invoice #],
    Item[Item #],
    Sales[Transaction Code],
    CustomerOnly, ShippedOnly, FiscalPeriod,
    "Sales Qty",   [Shipped Qty],
    "Gross Sales", [Gross Sales],
    "Net Cost",    [Customer Net Cost]
)
